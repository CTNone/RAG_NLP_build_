# TỔNG HỢP KIẾN THỨC DỰ ÁN RAG CHATBOT (Dành cho Phỏng vấn)

## 1. TỔNG QUAN DỰ ÁN
- Tên dự án: RAG Chatbot về Pittsburgh / CMU và VNU.
- Mục tiêu: Xây dựng một Chatbot có khả năng trả lời các câu hỏi chuyên sâu về Pittsburgh, Carnegie Mellon University (CMU) và Đại học Quốc gia Hà Nội (VNU).
- Kiến trúc chính: Retrieval-Augmented Generation (RAG) - Kết hợp giữa truy xuất thông tin (Retrieval) và tạo văn bản tự nhiên (Generation) để giảm thiểu ảo giác (hallucination) và cung cấp câu trả lời có tính chính xác cao dựa trên tài liệu thực tế.

## 2. CÁC CÔNG NGHỆ CHÍNH (TECH STACK)
- Ngôn ngữ: Python 3.8+
- Giao diện người dùng (UI): Gradio (giúp xây dựng web app Chatbot nhanh chóng với `gr.ChatInterface`).
- Large Language Model (LLM): Llama-3.3-70B-Instruct-Turbo-Free (được gọi qua API của Together AI).
- Embedding Model: intfloat/multilingual-e5-large-instruct (được gọi qua thư viện của Hugging Face). Hỗ trợ tốt đa ngôn ngữ (tiếng Anh và tiếng Việt).
- Vector Database: ChromaDB (lưu trữ và tìm kiếm vector nhúng của các đoạn tài liệu).

## 3. LUỒNG DỮ LIỆU (DATA PIPELINE)
1. Crawl Data: Thu thập dữ liệu từ Wikipedia và các trang web khác (code trong `craw_data_from_web.ipynb`).
2. Clean & Segment Data: Làm sạch và chia nhỏ văn bản (chunking) thành các đoạn văn bản (chunks) nhỏ hơn để đưa vào Vector DB (thực hiện trong `Clean_data.ipynb`).
   * Format dữ liệu chuẩn: JSON chứa `url`, `title`, và mảng `chunks` (các đoạn văn bản).
3. Create Vector DB: Chạy script `create_chroma_db.py` để nhúng (embed) các chunks và lưu vào ChromaDB.

## 4. LUỒNG TRUY VẤN RAG (RAG WORKFLOW)
Luồng này được triển khai trong file `app.py`:
1. User Query: Người dùng nhập câu hỏi trên giao diện Gradio.
2. Embedding Query: Câu hỏi của người dùng được chuyển đổi thành vector thông qua Embedding model.
3. Retrieval (Tìm kiếm ngữ cảnh): Dùng ChromaDB để tìm ra Top K (cấu hình biến `retriever_k`) đoạn tài liệu có vector gần nhất với vector của câu hỏi.
4. Prompt Construction: Kết hợp câu hỏi của người dùng và các đoạn văn bản truy xuất được vào một Prompt Template.
5. LLM Generation: Gửi prompt hoàn chỉnh cho mô hình Llama (qua Together AI) để tạo câu trả lời.
6. Trả về kết quả: Hiển thị câu trả lời cuối cùng cho người dùng trên Gradio.

## 5. NHỮNG ĐIỂM SÁNG CÓ THỂ TRÌNH BÀY TRONG PHỎNG VẤN
- Tối ưu chi phí và hiệu năng: Sử dụng các model mã nguồn mở mạnh mẽ như Llama 3 và các API (Together AI, Hugging Face) để giảm chi phí tự host LLM.
- Khả năng tinh chỉnh linh hoạt: Tách biệt cấu hình ra file `config.yaml` cho phép thay đổi nhanh:
  * Embedding Model: Dễ dàng đổi sang các mô hình nhỏ/nhanh hơn như `sentence-transformers/all-MiniLM-L6-v2` (22.7M params) hay `BAAI/bge-small-en-v1.5` để so sánh hiệu năng.
  * Thông số LLM: Điều chỉnh `temperature` (độ sáng tạo), `top_p`, `repetition_penalty` (chống lặp từ), và `max_new_tokens`.
  * RAG config: Dễ dàng thay đổi số lượng chunks `retriever_k`.
- Xử lý đa ngôn ngữ: Cấu hình embedding model `multilingual-e5-large` để xử lý tốt cả câu hỏi/tài liệu tiếng Việt (VNU) và tiếng Anh (CMU, Pittsburgh).
- Modular design: Source code được chia tách thành các module rõ ràng `src/database`, `src/llm`, `src/retriever`, `src/utils` giúp code dễ bảo trì và mở rộng.

## 6. CÂU HỎI PHỎNG VẤN THƯỜNG GẶP BẠN NÊN CHUẨN BỊ
1. Tại sao lại dùng RAG thay vì Fine-tuning LLM? (Đáp: RAG giúp LLM cập nhật kiến thức mới mà không cần train lại, giảm ảo giác (hallucination) vì có nguồn trích dẫn rõ ràng, chi phí thấp hơn).
2. Chunking size (kích thước chia nhỏ văn bản) ảnh hưởng thế nào đến RAG? (Đáp: Quá lớn sẽ lẫn nhiều thông tin nhiễu và tốn token, quá nhỏ sẽ mất ngữ cảnh. File JSON hiện tại đang chia văn bản theo các đoạn văn/phần có ý nghĩa).
3. Làm sao để đánh giá Chatbot này? (Đáp: Có thư mục `test_questions` và `test_answers` để đánh giá độ chính xác của câu trả lời so với tập mẫu).
